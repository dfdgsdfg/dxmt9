# Architecture Gap

Domain-owned implementation and evidence gap tracker. Use the [root gap index](../gap.md) for cross-domain rollup.

The PE ABI/codegen audit is now source-checked by
`scripts/check/audit_d3d9_pe_abi_codegen.py` and its stable manifest. Native
execution uses `--source-only`; x64/x86 artifact evidence must prove
`wine_builtin_dll=true`. State, draw, scene, and present bodies now remain in
the real `d3d9_pe_device.cpp` owner, while the compile-surface header has an
evidence-bounded 3,713-line residual containing the codegen-required in-class
bodies. No state implementation fragment remains. The cold StateBlock/FVF and
constant-validation helpers remain owned by the COM-cold TU. The audit excludes
addresses, timestamps, archive order, relocations, and whole assembly hashes.

## Architecture Layer

The final PE-device safety closure pins an honest 3,713-line compile-surface
residual for `d3d9_pe_device_impl.hpp`, with zero state fragments. Exact x64
and x86 codegen requires reachable in-class bodies for `SetStreamSource`,
`Present`, and `DrawIndexedPrimitive` plus the helper/template set named in
`pe_device_abi_manifest.toml`; all remaining hot definitions are physically
owned by `d3d9_pe_device.cpp`. `QueryInterface` remains the out-of-line key
function that fixes vtable and RTTI ownership in that TU; it is not used as a
surrogate anchor for out-of-line emission of the retained in-class bodies.

| PE device hot/cold decomposition (`R-ARCH-1.*`, `R-ARCH-5.*`) | ✅ | **Landed 2026-08-22 and safety-closed 2026-08-25.** `src/d3d9/d3d9_pe_device.cpp` began as one 16,451-line translation unit whose `D3D9DeviceImpl` class body held 453 members with every method defined in-class. The first eleven-step extraction reached an intermediate 5,965-line header plus seven 545-line `.inc.hpp` regions; that is historical evidence, not the current shape. The completed shape has no state implementation fragments, an honestly bounded 3,713-line compile-surface header, real subsystem TUs for cold owners, and the remaining hot definitions physically in `d3d9_pe_device.cpp`. Only `SetStreamSource`, `Present`, `DrawIndexedPrimitive`, and the manifest-listed helper/template bodies remain in-class because moving them changed x64 or x86 hot codegen. **Gate story:** early same-TU steps used object byte identity; cross-TU steps used normalized hot instruction metrics. | PE-side type-level safety (`R-ARCH-1.*` adjacent) | ⚠️ | **Measured 2026-08-22.** Across `src/d3d9/d3d9_pe_*` (~32k lines) versus `src/dxmt9/*`: `enum class` 20 vs 135, `constexpr bool` pure predicates **4 vs 151**, `static_assert` 30 vs 120, TLA+ binding comments ~17 vs 104, `std::variant` 0 in both (PE's single occurrence is a comment recording why one was rejected). The shared-pure-predicate discipline that binds a TLA+ action to production code and to a native spec (R-BACK-43.6 shape: `pendingInitializerReferenceSafe`, `drawableTokenMayFulfill`, `canReclaimRecord`) is therefore much less developed on the PE recorder path. **Architectural constraint:** the Windows-only `D3D9DeviceImpl` COM TUs in `dxmt9_pe_core_srcs` are not directly compiled or executed by the native host suite (0 such TU targets in `build`, 1 in `build-win32-x64-builtin`). The host lane can and does compile extracted PE-neutral headers and value owners such as `d3d9_pe_state_shadow.hpp`, the sparse producer, builder, registry predicates, and differential fixtures; it cannot substitute for PE COM execution. The acceptance shape is therefore shared host-buildable production predicates and differential value tests, unix-import validation, plus x64/x86 PE builds and Wine conformance — not a claim that the host suite observes nothing. **Closed so far:** typed slot keys for the state shadow (`98fceb13`) give the six index spaces — render-state, texture-stage, TSS type, sampler, sampler-state type, transform — distinct `enum class ... : std::uint32_t` keys, making cross-space indexing a compile error; zero runtime cost proven by `static_assert` on size/align/trivial-copyability, storage `sizeof` pinned to pre-change literals, and machine-code comparison (`producer.o` `__text` byte-identical, `process_vertices.o` `.text` size-identical). **Correction 2026-08-22:** an earlier draft of this row claimed the PE recorder's thread-affinity contract was "an ad-hoc assert plus an env override" and listed adopting `ThreadOwnershipToken` as outstanding work. That was wrong and was never checked before being written — the recorder already holds a `dxmt9::core::ThreadOwnershipToken recorderOwnership_` and asserts through `DXMT_ASSERT_OWNED_BY_OR_LOCKED(recorderOwnership_, recorderLockRequired_)`, and its own comment records that this site is the reference shape the shared helper was *extracted from*. PE led that pattern rather than lagging it. The error came from extrapolating a specific mechanism claim out of aggregate grep counts, which the metric caveat in this row explicitly warns against. **Migration completed 2026-08-23** (`04a898f4`, `ae1479a9`): every keyed table access across the five `D3D9DeviceImpl` TUs and the producer now goes through the typed views — zero untyped `get`/`set`/`contains`/`erase` remain — and the raw `PeHotStateShadow::renderStateEquals` convenience, left callerless by the migration, was deleted so no untyped door stays open. Codegen was verified rather than assumed: per-symbol instruction comparison of the hot object shows **all 24 hot methods instruction-identical**, and of 302 symbols only four differ — `InvalidateStateBlockShadowForChild` and its thunk at an unchanged 80 instructions, an `appendSingleCategoryApplyState` instantiation at an unchanged 118, and `drainOversizedPendingStateAsApplyStateRecords` at +3 (a bounded overflow-drain path, not per-draw). The typed views forward directly (`clear()` is `table_.clear()`), so those four are the compiler choosing a different but equivalent store sequence, not added work. **Still needed:** extract and share the recorder transition predicates required by `specs/d3d9/recorder/` and pair their native evidence with PE/Wine acceptance; making the whole COM TU host-buildable is optional, not the only path to a unit-level gate. |
