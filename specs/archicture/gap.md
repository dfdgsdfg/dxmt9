# Architecture Gap

Domain-owned implementation and evidence gap tracker. Use the [root gap index](../gap.md) for cross-domain rollup.

## Architecture Layer

| Area | Status | Notes |
|---|---|---|
| DOD / DXMT ownership acceptance (`R-ARCH-1.*`, `R-ARCH-2.*`, `R-ARCH-5.*`) | ⚠️ | `specs/archicture/` now owns the whole-project architecture contract and the chunk wire path is data-oriented. Merge-readiness still needs explicit acceptance that PE state shadow, POD chunk construction, unix import, queue execution, presentation pacing, and deferred resource safety each have matching implementation owners and tests |
| Minimal-copy policy (`R-ARCH-7.*`) | ⚠️ | New `requirements.md` §7 consolidates the warm-path copy floor. **Met:** allow-list (R-ARCH-7.1); reference-by-handle for large payloads (R-ARCH-7.3, `DrawUniformHandle` intern); construct-in-place constant upload (R-ARCH-7.4/7.5) — VS/PS dirty cbuf bytes now build directly into the shared `MTLStorageModeShared` transient slab via `buildAndPointEntryBytes` (`src/dxmt9/dxmt9_argbuf_hybrid.cpp`), removing the per-draw stack buffer + memcpy; byte-identical, covered by `dxmt9-argbuf-hybrid-spec`/`dxmt9-argbuf-populator-spec` and the R-BACK-12.27 runtime A/B equivalence harness. **Partially met by default:** R-ARCH-7.2 + carrier part of R-ARCH-7.4 now skips the `FlatDrawStateRecord`+`shaderLayout` copy for same `{stateGeneration,stateLane}` non-front submissions in `snapshotDrawSubmissionFromCurrentState` (`src/d3d9/core_draw.cpp`). `submitDrawRunBatch` (`src/dxmt9/dxmt9_command_queue.cpp`) keeps normal compatibility grouping and accepts elided candidates through the already accepted previous draw when needed; `DXMT9_DRAWRUN_GROUP_BY_GEN_LANE=1` remains only a stricter stamp-only diagnostic mode. Counters `d3d9_snapshot_state_{materialized,elided}{,_bytes}` and `submit_draw_run_batch_discarded_state_{records,bytes}` expose the copy-class proof. The 2026-06-14 3DMark05 GT1 default scout removes the measured discarded-state class (`411,362 -> 0` discarded records), elides `412,180` state copies / `4.217GB`, and cuts `d3d9_snapshot_state_copy_cpu_ms` `261.001 -> 138.856` with a normal output frame; GPU/completion remain flat/noisy, so this is copy-policy cleanup rather than the FPS owner. The adjacent uniform-payload extension is measured and rejected for GT1: state elision fires, but `d3d9_snapshot_uniform_elided=0`, so same-stamp groups still change uniform generation. **Still needed:** deeper producer-carrier/direct-construct work if R-ARCH-7.2/R-ARCH-7.4 are to remove the surviving front/materialized state carrier copy, plus continued no-gputrace/FPS evidence before treating copy cleanup as a pacing fix. Owners: `R-ARCH-7.2`, `R-ARCH-7.4`, `R-ARCH-7.6`. |
| PE-side type-level safety (`R-ARCH-1.*` adjacent) | ⚠️ | **Measured 2026-08-22.** Across `src/d3d9/d3d9_pe_*` (~32k lines) versus `src/dxmt9/*`: `enum class` 20 vs 135, `constexpr bool` pure predicates **4 vs 151**, `static_assert` 30 vs 120, TLA+ binding comments ~17 vs 104, `std::variant` 0 in both (PE's single occurrence is a comment recording why one was rejected). The shared-pure-predicate discipline that binds a TLA+ action to production code and to a native spec (R-BACK-43.6 shape: `pendingInitializerReferenceSafe`, `drawableTokenMayFulfill`, `canReclaimRecord`) is therefore almost entirely a unix-side achievement with no PE foothold. **Root cause, and the reason this is architectural rather than stylistic:** `d3d9_pe_device.cpp` and its siblings are in `dxmt9_pe_core_srcs`, compiled only `if host_machine.system() == 'windows'`, so **the host suite cannot compile or observe them at all** — verified: 0 targets in `build`, 1 in `build-win32-x64-builtin`. PE's safety story is consequently differential golden testing (`dxmt9-pe-producer-differential-spec`), value-level mirrors of pure validators, and validation at the unix import boundary — never type-level invariants, because there is no host lane in which to assert them. **Closed so far:** typed slot keys for the state shadow (`98fceb13`) give the six index spaces — render-state, texture-stage, TSS type, sampler, sampler-state type, transform — distinct `enum class ... : std::uint32_t` keys, making cross-space indexing a compile error; zero runtime cost proven by `static_assert` on size/align/trivial-copyability, storage `sizeof` pinned to pre-change literals, and machine-code comparison (`producer.o` `__text` byte-identical, `process_vertices.o` `.text` size-identical). **Still needed:** (a) migrate the ~71 untyped call sites now living in `d3d9_pe_device_impl.hpp` to the typed API — deferred because the hot/cold decomposition owned that file; (b) adopt the existing `ThreadOwnershipToken` for the PE recorder's thread-affinity contract, which is currently an ad-hoc assert plus an env override; (c) decide whether making `dxmt9_pe_core_srcs` host-buildable is worth it, since that, not more types, is what would give PE a unit-level behavioural gate. |
| Architecture concurrency model (`R-ARCH-6.*`) | ⚠️ | Queue, encoder, resource lifetime, present latency, and query sequence safety have TLA+ coverage and implementation assertions. `ConcurrentProgressSignals.tla` proves independence of the existing seqId, present-token, and ring axes. `R-ARCH-6.10/6.11` now define future encode-coordinator/partition-worker ownership and CPU-ready/session/partition pressure observations. Remaining: no bounded CPU-ready store or partition-worker agent exists, their admission/join models and counters are missing, and end-to-end observer evidence for fire-and-forget submission classes, ring back-pressure, explicit waits, and sidecar publication still needs an integrated acceptance pass. Detailed scheduling gaps are owned by `specs/backend/encode-scheduling/gap.md`. |
