# dxmt9 Environment Variables — PE bridge / recorder

Part of the [`environment_variables.rules.md`](environment_variables.rules.md)
index (PE-side chunk recorder diagnostics). A flag is "set" when its value is a
non-empty string that is not `0`, unless documented otherwise. See the index
for global notes.

## PE bridge / recorder

`DXMT9_OFFLOAD_COMMIT_REPLAY` and its inline rollback are stable producer-replay
providers. `DXMT9_CPU_READY_TAPE` is the migration alias for the stable
default-off streaming provider. Inline-constant delta remains an experimental
candidate; recorder stats, full snapshots, and queue-size overrides are
diagnostic or tuning surfaces rather than provider modes.

| Var | Purpose | Default |
|---|---|---|
| `DXMT9_PE_FORCE_RECORDER_LOCK` | Force `recorderMutex_` on even when the app did not pass `D3DCREATE_MULTITHREADED` in `CreateDevice`'s `BehaviorFlags`. Native D3D9 takes its device lock only under that flag; without it the app promises single-threaded access, and by default `D3D9DeviceImpl` skips the recursive-mutex lock/unlock on every PE recorder append (`recorderLockRequired_`, resolved once at construction via `dxmt9PeRecorderLockRequired()` in `src/d3d9/d3d9_pe_device.cpp`). Use this rollback/insurance lane for wild apps that violate the contract, such as releasing resources from a loader thread despite not passing the flag. A debug build additionally `DXMT_ASSERT`s that the calling thread matches the device-creating thread whenever the lock is skipped, so a real cross-thread violation aborts loudly instead of racing the unlocked recorder state | follows `D3DCREATE_MULTITHREADED` |
| `DXMT9_PE_RECORDER_STATS` | Emit PE recorder aggregate stats. Current fields include chunk fill/first-record/active-fill/inter-append cadence, top `previous record -> next record` inter-append pairs, focused inter-append pair call-family attribution, selected post-Present PE call return HRESULT rows including failure returns, append CPU, VS/PS float constant setter CPU, const-flush CPU, `chunkBarrierFlush` const-drain CPU, APPLY_STATE packet-build CPU, and PE hot-state setter family call/dirty/CPU counters | `0` |
| `DXMT9_PE_RECORDER_CHUNK_LOG` | Emit PE recorder chunk boundary logs | `0` |
| `DXMT9_PE_SCALAR_SEMANTIC_OBSERVER` | Allocate the cold 8,864-byte render/TSS/sampler source-ordinal ledger used by the bounded scalar projection audit. The default path retains no ledger in `PeRecorderState`; typed settlement still checks canonical order and exact PendingDelta category/key/index/value without this observer. Enabling it adds exact setter-source and builder-record ordinals for native/formal witness diagnostics, one cached nullable-owner branch per affected setter/settlement, and no per-setter allocation or virtual dispatch. This is proof instrumentation, not a performance mode or proof of the default path's source ordinal because no such ordinal is retained when the gate is off. | `0` |
| `DXMT9_PE_INLINE_CONST_DELTA` | Experimental candidate that emits pending VS/PS constant dirty ranges inside canonical draw-record constant sections instead of standalone constant records. The mechanism is covered and removes records, but H214's FPS result stayed inside noise; the stable fallback preserves standalone record ordering, and non-draw consumers plus UP draws still drain standalone records. | `0` |
| `DXMT9_PE_STATS_DECIMATION` | Low-perturbation alternative to `DXMT9_PE_RECORDER_STATS` for sizing the PE recorder core: numeric `N` samples every Nth event of the four hot scopes (the record append, `touchConstShadow`, `flushConstShadow`, and the state build -- still keyed `draw_packet_*` in the log, now timing `buildSparseState`) and emits a cumulative `[dxmt9-pe-decimated]` line every 60 presents at Info level (run with `DXMT_LOG_LEVEL=info`). Estimate per scope as `sampled_ms * N / presents`, **then subtract the instrument's own cost**: the same log line carries `null_scope_sampled` / `null_scope_ms`, an empty region timed with the identical clock pair, and the scope's real per-call cost is `raw_mean - null_mean`. This is not optional. Measured on GT2 2026-07-29 the clock pair costs `186 ns` per sample, which is `6%` of `appendRecordDirect`'s reading and **`92%`** of `touchConstShadow`'s — an uncalibrated reading put PE recording at `30.5%` of the frame when it is `16.1%`. Low perturbation and low bias are different properties: decimation delivers the first and nothing about the second, and varying `N` cannot expose it because the extrapolation reduces to `events * (true + bias) / presents`, independent of `N`. The tool is unusable for absolute cost wherever per-call cost approaches clock cost. Since 2026-08-01 it also carries three **D3D9 entry-level** scopes (`entry_const`, `entry_draw`, `entry_state`) covering the whole call the app made across 14 hot entry points, so `entry - inner` sizes the PE layer the four recorder scopes never saw; on GT2 that residual is `~15.4 ms/present` and the entry total is `~41%` of the frame (`state-churn-encode-append-decomposition.08`; `12.0` of that `21.4 ms` — `56%` of the entry total, `22.6%` of the frame — was an SWVP probe removed in `83a0b085` for `+29%` GT2 scene fps, `.11`). New scopes must be armed with `dxmt9PeArmDecimatedScope`, which performs the null-scope calibration read — the instrument costs ~180ns/sample and an uncalibrated short scope is wrong by more than it measures. **A new scope must also pick a `phaseOffset` distinct from any scope it nests inside or contains on the same calls.** Sampling is deterministic (`events % N == phaseOffset % N`), so two scopes whose counters advance in lockstep fire on identical call ordinals at every `N`, and the outer span then swallows the inner scope's entire instrument — calibration pair, `t0`, and destructor read — while its own null subtraction removes one. That put `entry_const` at `756 ns/call` (`16.5 ms/present`) when the truth is `~79 ns`, measured directly after the fix (`.10`); `N`-variation cannot expose it because the coincidence is total at every `N`. `peConstSetterDecimatedStats()` is phase `1` and `peDrawPacketDecimatedStats_` phase `2` for exactly this reason, and `dxmt9-core-device-com-spec` pins both the fix and the old coinciding shape. Parent-gated sub-scopes (`DxmtPeDecimatedPhaseTimer`) are exempt — they cost their parent one clock pair each, a known subtractable constant. Separately, avoid an `N` that divides a periodic structure in the measured population: both `64` and `16` divide the 64-record chunk period, which aliases `append`'s once-per-64 flush tail and explains its `12.8%` cross-rate disagreement. `const_setter` samples are additionally split into per-call register-count buckets (`const_setter_n{1,2,3_4,5_8,9_16,gt16}_*`) so flat-versus-sloping cost distinguishes fixed entry overhead from per-element work. H213 verified `N=64`/`N=16` runs stay inside the healthy presents population (vs `-34%` throughput for full stats) and agree within `+/-12%` per site. Independent of `DXMT9_PE_RECORDER_STATS`; `0`/unset disables with near-zero cost | `0` |
| `DXMT9_BRIDGE_PERF_PERIODIC_COMMITS` | Emit the cumulative `[dxmt9-bridge-perf]` per-class/per-detail crossing report every N `commit_chunk` crossings (requires `DXMT_PERF_COUNTERS`). Commit crossings are the trigger because Present rides the chunk as a record and never appears as a standalone bridge call; the atexit-only report is lost on a SIGKILLed run (the H231 lesson in bridge form). Use ~1000 for GT2 crossing-cost decomposition | `0` |
| `DXMT9_PE_MODULE_MAP` | Diagnostic (Tier 1 of PE 32-bit symbolication): at device creation, dump every loaded module's `base`/`size` plus one in-module probe address as `[dxmt9-pe-module-map]` Info lines, so xctrace `time-profile` samples of the otherwise-opaque 32-bit game thread can be classified per module by `scripts/tools/symbolicate_xctrace_pe.py` (the probe must land inside our own `d3d9.dll` range or the join refuses). Zero cost unset; run with `DXMT_LOG_LEVEL=info` | `0` |
| `DXMT9_PE_THREAD_SAMPLER` | Diagnostic (Tier 2 of PE 32-bit symbolication, and the **working** one on Apple Silicon). At device creation, spawn one sampler thread that repeatedly `SuspendThread`s the thread that created the device — the game thread — reads its true Win32 program counter with `GetThreadContext(CONTEXT_CONTROL)`, resumes it, and classifies the PC against a Toolhelp32 module map built once at sampler start. Tier 1 (`DXMT9_PE_MODULE_MAP` + xctrace) cannot reach this data at all: PE x86 runs Rosetta-translated and Instruments only maps translated PCs back for dyld images, so 92.7% of game-thread samples land as `unknown_64bit` (measured 2026-08-19). Emits cumulative `[dxmt9-pe-sampler]` Info groups every 60 presents plus one at device teardown, so **read the last group** — counters never reset. A group is a header line (`presents= samples= suspend_failures= ctx_failures= resume_failures= hz= module_table=`), one `module=<name> samples=<n>` line per module with a nonzero count (top 20, ties by enumeration order, with a synthetic `unknown` row for PCs outside every mapped range), `selfpc_module=<name>`, up to 32 `selfpc bucket=0x<hex> samples=<n>` rows (64-byte PC buckets inside our own `d3d9.dll`), and `selfpc_overflow=<n>`. **A run with this set is NOT a valid performance sample**: it stops the game thread `hz` times a second. Requires `DXMT_LOG_LEVEL=info` for the emission, and pairs with `DXMT9_PE_MODULE_MAP=1` — the join needs that log's `base=` to turn a self-PC bucket into an RVA. Join with `scripts/run_python.sh scripts/tools/symbolicate_xctrace_pe.py --sampler-log <run.log> --output-csv <out.csv> --output-md <out.md>`, which also writes `<out>-selfpc.csv`. Only one sampler runs per process (a second device does not add a second thread stopping the same target). It targets the **device-creating** thread; if an app presents from a different thread the samples describe the wrong one, so the first Present emits a one-shot `target_thread_mismatch sampled=0x.. present=0x..` line — treat that line as invalidating the run rather than as a warning. Implementation and the suspend-window safety contract: `src/d3d9/d3d9_pe_thread_sampler.hpp`; its pure core is pinned by `dxmt9-pe-thread-sampler-spec`. Late-loaded DLLs are not in the module table and count as `unknown`. Zero cost unset | `0` |
| `DXMT9_PE_THREAD_SAMPLER_HZ` | Sampling rate for `DXMT9_PE_THREAD_SAMPLER`, clamped to `[50, 1000]`. Unset, `0`, and unparseable values resolve to the default rather than the floor. The wait interval is `1000/hz` ms, so above `1000` Hz the scheduler, not this knob, sets the rate | `250` |
| `DXMT9_PE_DRAW_FULL_SNAPSHOT` | Force every draw packet to ride a full PE state snapshot instead of the default delta. Applied in `src/d3d9/d3d9_pe_producer.cpp::buildSparseState` (the `snapshot` gate); the predicate itself is `dxmt9PeFullSnapshotEnabled()` in `src/d3d9/d3d9_pe_producer.hpp`. Trade-off: wire size grows ~10x (typical record ~100 B → ~1 KB), every draw carries a full state section set so none can be elided, but each record is replayable in isolation — debug / stress / out-of-order-replay only. The bounded Render Tape `executable-project` lane does not require this setting: its cold projector folds the canonical BootstrapState and preceding default sparse records into one validated child bootstrap. Equivalence with the default delta path is regression-guarded by `tests/native/bridge/pe_full_snapshot_equivalence_spec.cpp`. | `0` |
| `DXMT9_PE_STATEBLOCK_FAULT` | Bounded, one-shot StateBlock fault seam for PE transaction evidence; unset/empty is the production path and costs only the cached cold-call gate. Set a comma-separated point list (`capture_pre`, `apply_pre`, `end_pre`, `alloc_pre`, `capture_entered`, `apply_entered`, `end_entered`, or `bridge_entered`), optionally with an exact unsigned HRESULT (`capture_pre=0x80004005`). Pre-effect points return the exact HRESULT while preserving state for retry; entered points return an effect-unknown HRESULT, release staged references, and poison until a successful Reset. `alloc_pre` is checked before StateBlock creation/publication work and defaults to `E_OUTOFMEMORY`; each point is consumed once per process. Diagnostic/test-only; never use it to claim an entered call was recoverable. | unset |
| `DXMT9_PE_CHUNK_MAX_RECORDS` | Override max pending PE chunk records before commit. The default was promoted to `256` on 2026-08-19 (with `DXMT9_PE_CHUNK_MAX_BYTES=1310720` — both must move together because the frozen legacy sizeHints make the byte precheck bind near 53 draw records at the old byte cap) after the full gate matrix in `docs/perfomance/state-churn-encode/state-churn-encode-append-decomposition.22.md`: GT2 median +2.0% (non-overlapping ABBA), GT1 +3.5%, GT3 +2.5%, SFIV percentile-equal, byte-identical CB/pass/subCB locality, conserved encode pacing, normal visuals, zero GPU errors — mechanism is 44→8 chunk seals/present returning ~1.2ms/present of game-thread CPU. Explicit `64` (with `262144`) restores the pre-promotion cadence for rollback/A-B | `256` |
| `DXMT9_PE_CHUNK_MAX_BYTES` | Override max pending PE chunk bytes before commit; promoted default pairs with the records row above, rollback pair `64`/`262144` | `1310720` |
| `DXMT9_RENDER_TAPE_CAPTURE` | Opt-in PE Render Tape v2 capture owner. `1` enables the device-owned value registry at device creation; the first successful Present builds a canonical `APPLY_STATE|FULL_SNAPSHOT` checkpoint from the PE shadow, closes exact descriptors, immutable payloads, and complete CPU-owned resource seeds, and arms the next Present interval when an artifact publisher is installed. When both capture and `DXMT9_RENDER_TAPE_OUTPUT_ROOT` are set, the unix backend selects the production streaming source provider with a capture-only 8-MiB Arena (2,048 4-KiB pages). EventSerial/default capture retains its 512-page queue admission bound; only an authenticated token+event-ordinal capture event selected for queue-immutable `DXMT9_RENDER_IDENTITY_MODE=segment` applies the call-local 64-page-per-source planner bound, so startup/non-capture records and EventSerial remain 512 pages/source. Canonical events exceeding one SegmentSerial source are split into ordered sources through the atomic Arena batch lease, with all-or-nothing Ready publication/abort. Capture without an output publisher and capture-off do not select it or change ordinary streaming bounds. The captured standard Present records a `PresentComplete` SHA-256 from a typed one-shot Presenter mirror at the logical captured backbuffer extent. An injected bootstrap producer is only an explicit test override. Publication is transactional as one value-owned events-plus-verified-blobs bundle with a 256 MiB default total owned-blob budget; `DXMT9_RENDER_TAPE_MAX_BLOB_BYTES` is read only when capture is enabled, parses decimal bytes, uses the default for unset/invalid/zero, and clamps valid values above the hard 1 GiB ceiling to that ceiling. Capture-off leaves callbacks, registry allocation, the recorder, canonical chunk bytes, and the override read untouched. | `0` |
| `DXMT9_RENDER_TAPE_MAX_BLOB_BYTES` | Capture-only total owned-blob byte limit in decimal bytes. Unset, invalid, or zero uses the 256 MiB default; valid values above the hard 1 GiB ceiling resolve to 1 GiB. The limit is passed to the existing PE capture session, whose overflow-safe admission and all digest, descriptor, generation, event, and replay validation remain unchanged. It is not read when `DXMT9_RENDER_TAPE_CAPTURE` is off. | `268435456` |
| `DXMT9_RENDER_TAPE_PROFILE` | Optional explicit profile selector used with `DXMT9_RENDER_TAPE_CAPTURE=1`: `frame-tape` (default) captures one standard Present interval; `sequence-tape` captures exactly two consecutive standard Present intervals and requires one complete digest-backed resource mutation between them. Unknown values disable capture fail-closed. | `frame-tape` |
| `DXMT9_RENDER_TAPE_OUTPUT_ROOT` | Explicit **PE-visible absolute directory** under which the internal PE publisher creates unique `<profile>-<monotonic>-<sequence>/` bundles (`frame-*` or `sequence-*`). Under Wine this means a Windows drive-qualified path such as `Z:\\...`, not a host-only POSIX path. Relative roots, traversal components, NULs, symlink components, and existing-name collisions are rejected; staging is same-filesystem and renamed atomically only after `events.bin`, `identity.bin`, optional `output.rgba`, optional `source.rgba`, digest-named `blobs/`, and `manifest.json` are flushed. `source.rgba` is a capture-only source-before-Present diagnostic sidecar and never a replay input. Unset means the production publisher is not installed and capture remains inert; it does not define the canonical output digest domain. | unset |
| `DXMT9_OFFLOAD_COMMIT_REPLAY` | Stable producer-replay provider selector: `0` keeps inline replay and `1` defers record replay to a device-owned FIFO worker after synchronous validation/import/retention. Both modes preserve direct-call drains and Present-boundary semantics under `R-BACK-2.51`; replay failures fail-stop the worker. Promotion proof passed in H195, and the engine default flipped to offloaded on 2026-07-10 (`d45af067`); explicit `0` remains the supported rollback. The experiment launcher pins the value only for recipe determinism and does not define the engine default. `DXMT9_OPTIMIZE_OPAQUE_DEPTH_INDEX_CACHE` unset follows the resolved offload state as an explicit coupled policy. | `1` (engine; explicit `0` opts out) |
| `DXMT9_MANAGED_MUTATION_OFFLOAD` | Stable provider mode (R-BACK-44, `specs/backend/buffer-mutation-offload/`): defer the byte materialization of **plain** Managed-pool writable buffer unlocks (no DISCARD/NOOVERWRITE/READONLY flags) to the commit-replay offload worker at the unlock's FIFO position, replacing the R-BACK-2.51(d) pre-mutation drain with ordered admission per clause (d)(iv). The synchronous half stages the dirty span, performs the logical backing rotation, and commits a reserved queue task; the worker copy-forwards from the pool shadow and patches the leased backing. Requires `DXMT9_OFFLOAD_COMMIT_REPLAY` active. Promoted to **engine default ON 2026-08-25** after the R-BACK-44.8 gates: TLA + counterexamples, D3D9 conformance with the mode on, GT1/GT3/SFIV visual anchors, conserved CB/pass locality, and a GT2 matched A/B (harmonic `27.605 -> 28.864`, `+4.6%`, managed full uploads `1,227 -> 0`, zero GPU errors). Explicit `0` is the supported byte-identical rollback lane | `1` (engine; explicit `0` opts out) |
| `DXMT9_CPU_READY_TAPE` | Migration alias for the stable `streaming` source-delivery provider in `R-BACK-2.66`. With commit-replay offload active, eligible canonical chunks reserve bounded `CpuReadyTape` storage and publish typed source payloads; ordered Legacy/Inline/control fallbacks remain valid. Streaming remains default off pending `R-BACK-2.50` visual, locality, no-gputrace, and performance gates, but the mode is a preserved renderer-provider path rather than a disposable experiment. A production Render Tape capture with an installed output publisher selects the same provider independently so authoritative capture identity can be emitted; that diagnostic selection does not promote streaming for ordinary rendering. A future canonical source selector will take precedence after it is implemented and added to these descriptive rules. | `0` |
| `DXMT9_OFFLOAD_QUEUE_CHUNKS` / `DXMT9_OFFLOAD_QUEUE_BYTES` | Raw-chunk queue bounds for the commit-replay offload worker (count / bytes). H191 attribution showed the defaults never block a push in GT1 (`offload_push_backpressure_waits=0`), so these are dormant tuning knobs, not active levers | `64` / `8388608` |
