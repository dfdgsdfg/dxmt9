# dxmt9 Environment Variables — PE bridge / recorder

Part of the [`environment_variables.rules.md`](environment_variables.rules.md)
index (PE-side chunk recorder diagnostics). A flag is "set" when its value is a
non-empty string that is not `0`, unless documented otherwise. See the index
for global notes.

## PE bridge / recorder

| Var | Purpose | Default |
|---|---|---|
| `DXMT9_PE_RECORDER_STATS` | Emit PE recorder aggregate stats. Current fields include chunk fill/first-record/active-fill/inter-append cadence, top `previous record -> next record` inter-append pairs, focused inter-append pair call-family attribution, selected post-Present PE call return HRESULT rows including failure returns, append CPU, VS/PS float constant setter CPU, const-flush CPU, `chunkBarrierFlush` const-drain CPU, APPLY_STATE packet-build CPU, and PE hot-state setter family call/dirty/CPU counters | `0` |
| `DXMT9_PE_RECORDER_CHUNK_LOG` | Emit PE recorder chunk boundary logs | `0` |
| `DXMT9_PE_STATS_DECIMATION` | Low-perturbation alternative to `DXMT9_PE_RECORDER_STATS` for sizing the PE recorder core: numeric `N` samples every Nth event of the four hot scopes (`appendRecordDirect`, `touchConstShadow`, `flushConstShadow`, `buildDrawPrimitivePacket`) and emits a cumulative `[dxmt9-pe-decimated]` line every 60 presents at Info level (run with `DXMT_LOG_LEVEL=info`). Estimate per scope as `sampled_ms * N / presents`. H213 verified `N=64`/`N=16` runs stay inside the healthy presents population (vs `-34%` throughput for full stats) and agree within `+/-12%` per site. Independent of `DXMT9_PE_RECORDER_STATS`; `0`/unset disables with near-zero cost | `0` |
| `DXMT9_PE_DRAW_FULL_SNAPSHOT` | Force every draw packet to ride a full PE state snapshot instead of the default delta. Applied in `src/d3d9/d3d9_pe_device.cpp::buildDrawPrimitivePacket` (lines ~497-583 under `if (dxmt9PeFullSnapshotEnabled())`). Trade-off: wire size grows ~10x (typical packet ~100 B → ~1 KB), the importer's run-coalescer (`packetHasNoStateDelta`) sees no empty packets so every draw breaks the coalesced run, but each packet is replayable in isolation — debug / stress / out-of-order-replay only. Equivalence with the default delta path is regression-guarded by `tests/native/bridge/pe_full_snapshot_equivalence_spec.cpp`. | `0` |
| `DXMT9_PE_CHUNK_MAX_RECORDS` | Override max pending PE chunk records before commit | `64` |
| `DXMT9_PE_CHUNK_MAX_BYTES` | Override max pending PE chunk bytes before commit | `262144` |
| `DXMT9_OFFLOAD_COMMIT_REPLAY` | Experimental producer-serial reduction: `dxmt9c_device_commit_chunk` keeps validation/import/handle-marking synchronous but defers record replay to a device-owned worker through a bounded raw-chunk queue (wire bytes copied, wrappers addref'd). Present-bearing commits wait an app-side present-ordinal frame-latency boundary honoring the `DXMT9_PRESENT_BOUNDARY_*` policy resolution and, since the 2026-07-10 fix, `DXMT9_CAP_FRAME_LATENCY_TO_BACKBUFFERS` too (capped via `dxmt9::cappedFrameLatency`, identically to the inline boundary — this closes the former "known niche" gap). `CommandQueue::submitPresent` suppresses its inline boundary only per-present, for the specific present that ordinal wait just paced (`core::SwapDesc::pacedByPresentOrdinal`, set only by the D3D9 chunk-replay path) — a direct (non-chunk) COM present in the same process still gets the inline boundary even while this flag is on (this closes the former global-only-suppression bug; both fixes are `dxmt9::resolvePresentBoundaryAction` / R-BACK-2.51(g)/(h)). Direct device calls drain the queue first. Replay failures fail-stop the worker and poison later commits instead of returning per-record HRESULTs. Promotion proof passed (H195 / `index-cache-locality-offload-promotion-proof.20`: runtime `+10-12%` FPS, frame60 target GPU `-7.39%`), so the shared `DXMT_EXPERIMENT_PROFILE=perf` launcher profile defaults it to `1` paired with `DXMT9_OPTIMIZE_OPAQUE_DEPTH_INDEX_CACHE=1`; `run_3dmark05_perf_probe.sh` pins it back to explicit caller env (default off) so probe recipes and A/B baselines keep their historical shape (`specs/backend/spec.md` §Commit-Replay Offload, R-BACK-2.51). **Engine default flipped to ON 2026-07-10** (`d45af067`) after all three blockers fell: per-present boundary suppression + ordinal latency cap (`72132513`, clauses (g)/(h)) and the native-spec harness drain gap that masqueraded as heap corruption (`cad446ce` — the specs passed stack-allocated wire wrappers and bypassed the `drainDeferredReplay()` fence every real bridge call gets; regression-pinned by the `-offload` spec variants). Explicit `0` opts out. `DXMT9_OPTIMIZE_OPAQUE_DEPTH_INDEX_CACHE` unset follows the offload state (coupled pair). Pure engine-default runtime proof: no pair env anywhere, `2,220` presents, trio counters live, `present_boundary_skipped` exactly `1.0/present` (only chunk-replay presents skip the inline boundary; direct COM presents keep it) | `1` (engine; explicit `0` opts out) |
| `DXMT9_OFFLOAD_QUEUE_CHUNKS` / `DXMT9_OFFLOAD_QUEUE_BYTES` | Raw-chunk queue bounds for the commit-replay offload worker (count / bytes). H191 attribution showed the defaults never block a push in GT1 (`offload_push_backpressure_waits=0`), so these are dormant tuning knobs, not active levers | `64` / `8388608` |
