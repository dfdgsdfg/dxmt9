# dxmt9 Environment Variables — PE bridge / recorder

Part of the [`environment_variables.rules.md`](environment_variables.rules.md)
index (PE-side chunk recorder diagnostics). A flag is "set" when its value is a
non-empty string that is not `0`, unless documented otherwise. See the index
for global notes.

## PE bridge / recorder

| Var | Purpose | Default |
|---|---|---|
| `DXMT9_PE_RECORDER_STATS` | Emit PE recorder aggregate stats. Current fields include chunk fill/first-record/active-fill/inter-append cadence, top `previous record -> next record` inter-append pairs, focused inter-append pair call-family attribution, selected post-Present PE call return HRESULT rows including failure returns, append CPU, VS/PS float constant setter CPU, const-flush CPU, `chunkBarrierFlush` const-drain CPU, APPLY_STATE packet-build CPU, and PE hot-state setter family call/dirty/CPU counters | `0` |
| `DXMT9_PE_RECORDER_CHUNK_LOG` | Emit PE recorder chunk boundary logs | `0` |
| `DXMT9_PE_FLUSH_AFTER_CLEAR` | Diagnostic PE-recorder pacing probe. After a `Clear` record is appended, immediately flush the pending command chunk with reason `clear` instead of waiting for the normal record/byte capacity threshold. Use only for 3DMark05 no-gputrace A/Bs that test whether an earlier useful chunk after the post-Present `Clear` gate creates producer overlap; not a default performance policy | `0` |
| `DXMT9_PE_FLUSH_AFTER_DRAW` | Diagnostic PE-recorder pacing probe. After each draw record is appended, immediately flush the pending command chunk with reason `draw` instead of waiting for the normal record/byte capacity threshold. Use only for paired 3DMark05 no-gputrace P4 scouts that test whether the dominant post-draw inter-append gap can be overlapped by earlier unix replay; expect many more PE commits and verify command-buffer/render-pass locality before reading FPS | `0` |
| `DXMT9_PE_DRAW_FULL_SNAPSHOT` | Force every draw packet to ride a full PE state snapshot instead of the default delta. Applied in `src/d3d9/d3d9_pe_device.cpp::buildDrawPrimitivePacket` (lines ~497-583 under `if (dxmt9PeFullSnapshotEnabled())`). Trade-off: wire size grows ~10x (typical packet ~100 B → ~1 KB), the importer's run-coalescer (`packetHasNoStateDelta`) sees no empty packets so every draw breaks the coalesced run, but each packet is replayable in isolation — debug / stress / out-of-order-replay only. Equivalence with the default delta path is regression-guarded by `tests/native/bridge/pe_full_snapshot_equivalence_spec.cpp`. | `0` |
| `DXMT9_PE_CHUNK_MAX_RECORDS` | Override max pending PE chunk records before commit | `64` |
| `DXMT9_PE_CHUNK_MAX_BYTES` | Override max pending PE chunk bytes before commit | `262144` |
| `DXMT9_OFFLOAD_COMMIT_REPLAY` | Experimental producer-serial reduction: `dxmt9c_device_commit_chunk` keeps validation/import/handle-marking synchronous but defers record replay to a device-owned worker through a bounded raw-chunk queue (wire bytes copied, wrappers addref'd). Present-bearing commits wait an app-side present-ordinal frame-latency boundary honoring the `DXMT9_PRESENT_BOUNDARY_*` policy resolution, and `CommandQueue::submitPresent` suppresses its inline boundary. Direct device calls drain the queue first. Replay failures fail-stop the worker and poison later commits instead of returning per-record HRESULTs. Promotion proof passed (H195 / `index-cache-locality-offload-promotion-proof.20`: runtime `+10-12%` FPS, frame60 target GPU `-7.39%`), so the shared `DXMT_EXPERIMENT_PROFILE=perf` launcher profile now defaults it to `1` paired with `DXMT9_OPTIMIZE_OPAQUE_DEPTH_INDEX_CACHE=1`; `run_3dmark05_perf_probe.sh` pins it back to explicit caller env (default off) so probe recipes and A/B baselines keep their historical shape (`specs/backend/spec.md` §Commit-Replay Offload, R-BACK-2.51). Engine default stays `0`. Caveats blocking an unconditional engine default: with the flag set, non-PE (direct COM) clients of the same process lose the inline present boundary — PE use only; the ordinal wait uses the raw `maxFrameLatency` and does not honor `DXMT9_CAP_FRAME_LATENCY_TO_BACKBUFFERS` | `0` (engine); `1` in the `perf` launcher profile |
| `DXMT9_OFFLOAD_QUEUE_CHUNKS` / `DXMT9_OFFLOAD_QUEUE_BYTES` | Raw-chunk queue bounds for the commit-replay offload worker (count / bytes). H191 attribution showed the defaults never block a push in GT1 (`offload_push_backpressure_waits=0`), so these are dormant tuning knobs, not active levers | `64` / `8388608` |
