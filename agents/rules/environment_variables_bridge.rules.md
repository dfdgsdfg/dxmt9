# dxmt9 Environment Variables — PE bridge / recorder

Part of the [`environment_variables.rules.md`](environment_variables.rules.md)
index (PE-side chunk recorder diagnostics). A flag is "set" when its value is a
non-empty string that is not `0`, unless documented otherwise. See the index
for global notes.

## PE bridge / recorder

| Var | Purpose | Default |
|---|---|---|
| `DXMT9_PE_RECORDER_STATS` | Emit PE recorder aggregate stats. Current fields include chunk fill/first-record/active-fill/inter-append cadence, top `previous record -> next record` inter-append pairs, focused inter-append pair call-family attribution, selected post-Present PE call return HRESULT rows including failure returns, append CPU, VS/PS float constant setter CPU, const-flush CPU, `chunkBarrierFlush` const-drain CPU, APPLY_STATE packet-build CPU, and PE hot-state setter family call/dirty/CPU counters | `0` |
| `DXMT9_PE_RECORDER_CHUNK_LOG` | Emit PE recorder chunk boundary logs | `0` |
| `DXMT9_PE_STATS_DECIMATION` | Low-perturbation alternative to `DXMT9_PE_RECORDER_STATS` for sizing the PE recorder core: numeric `N` samples every Nth event of the four hot scopes (the record append, `touchConstShadow`, `flushConstShadow`, and the state build -- still keyed `draw_packet_*` in the log, now timing `buildSparseStateV2`) and emits a cumulative `[dxmt9-pe-decimated]` line every 60 presents at Info level (run with `DXMT_LOG_LEVEL=info`). Estimate per scope as `sampled_ms * N / presents`, **then subtract the instrument's own cost**: the same log line carries `null_scope_sampled` / `null_scope_ms`, an empty region timed with the identical clock pair, and the scope's real per-call cost is `raw_mean - null_mean`. This is not optional. Measured on GT2 2026-07-29 the clock pair costs `186 ns` per sample, which is `6%` of `appendRecordDirect`'s reading and **`92%`** of `touchConstShadow`'s — an uncalibrated reading put PE recording at `30.5%` of the frame when it is `16.1%`. Low perturbation and low bias are different properties: decimation delivers the first and nothing about the second, and varying `N` cannot expose it because the extrapolation reduces to `events * (true + bias) / presents`, independent of `N`. The tool is unusable for absolute cost wherever per-call cost approaches clock cost. `const_setter` samples are additionally split into per-call register-count buckets (`const_setter_n{1,2,3_4,5_8,9_16,gt16}_*`) so flat-versus-sloping cost distinguishes fixed entry overhead from per-element work. H213 verified `N=64`/`N=16` runs stay inside the healthy presents population (vs `-34%` throughput for full stats) and agree within `+/-12%` per site. Independent of `DXMT9_PE_RECORDER_STATS`; `0`/unset disables with near-zero cost | `0` |
| `DXMT9_PE_DRAW_FULL_SNAPSHOT` | Force every draw packet to ride a full PE state snapshot instead of the default delta. Applied in `src/d3d9/d3d9_pe_producer.cpp::buildSparseStateV2` (the `snapshot` gate); the predicate itself is `dxmt9PeFullSnapshotEnabled()` in `src/d3d9/d3d9_pe_producer.hpp`. Trade-off: wire size grows ~10x (typical record ~100 B → ~1 KB), every draw carries a full state section set so none can be elided, but each record is replayable in isolation — debug / stress / out-of-order-replay only. Equivalence with the default delta path is regression-guarded by `tests/native/bridge/pe_full_snapshot_equivalence_spec.cpp`. | `0` |
| `DXMT9_PE_CHUNK_MAX_RECORDS` | Override max pending PE chunk records before commit | `64` |
| `DXMT9_PE_CHUNK_MAX_BYTES` | Override max pending PE chunk bytes before commit | `262144` |
| `DXMT9_OFFLOAD_COMMIT_REPLAY` | Experimental producer-serial reduction: `dxmt9c_device_commit_chunk` keeps validation/import/handle-marking synchronous but defers record replay to a device-owned worker through a bounded raw-chunk queue (wire bytes copied, wrappers addref'd). Present-bearing commits wait an app-side present-ordinal frame-latency boundary honoring the `DXMT9_PRESENT_BOUNDARY_*` policy resolution and, since the 2026-07-10 fix, `DXMT9_CAP_FRAME_LATENCY_TO_BACKBUFFERS` too (capped via `dxmt9::cappedFrameLatency`, identically to the inline boundary — this closes the former "known niche" gap). `CommandQueue::submitPresent` suppresses its inline boundary only per-present, for the specific present that ordinal wait just paced (`core::SwapDesc::pacedByPresentOrdinal`, set only by the D3D9 chunk-replay path) — a direct (non-chunk) COM present in the same process still gets the inline boundary even while this flag is on (this closes the former global-only-suppression bug; both fixes are `dxmt9::resolvePresentBoundaryAction` / R-BACK-2.51(g)/(h)). Direct device calls drain the queue first. Replay failures fail-stop the worker and poison later commits instead of returning per-record HRESULTs. Promotion proof passed (H195 / `index-cache-locality-offload-promotion-proof.20`: runtime `+10-12%` FPS, frame60 target GPU `-7.39%`), so the shared `DXMT_EXPERIMENT_PROFILE=perf` launcher profile defaults it to `1` paired with `DXMT9_OPTIMIZE_OPAQUE_DEPTH_INDEX_CACHE=1`; `run_3dmark05_perf_probe.sh` pins an explicit value for recipe determinism, and since 2026-07-12 the pinned default matches the engine default (on) — export `0` to opt out; historical default-off A/B recipes must pass `0` explicitly (`specs/backend/spec.md` §Commit-Replay Offload, R-BACK-2.51). **Engine default flipped to ON 2026-07-10** (`d45af067`) after all three blockers fell: per-present boundary suppression + ordinal latency cap (`72132513`, clauses (g)/(h)) and the native-spec harness drain gap that masqueraded as heap corruption (`cad446ce` — the specs passed stack-allocated wire wrappers and bypassed the `drainDeferredReplay()` fence every real bridge call gets; regression-pinned by the `-offload` spec variants). Explicit `0` opts out. `DXMT9_OPTIMIZE_OPAQUE_DEPTH_INDEX_CACHE` unset follows the offload state (coupled pair). Pure engine-default runtime proof: no pair env anywhere, `2,220` presents, trio counters live, `present_boundary_skipped` exactly `1.0/present` (only chunk-replay presents skip the inline boundary; direct COM presents keep it) | `1` (engine; explicit `0` opts out) |
| `DXMT9_OFFLOAD_QUEUE_CHUNKS` / `DXMT9_OFFLOAD_QUEUE_BYTES` | Raw-chunk queue bounds for the commit-replay offload worker (count / bytes). H191 attribution showed the defaults never block a push in GT1 (`offload_push_backpressure_waits=0`), so these are dormant tuning knobs, not active levers | `64` / `8388608` |
