# dxmt9 Environment Variables — PE bridge / recorder

Part of the [`environment_variables.rules.md`](environment_variables.rules.md)
index (PE-side chunk recorder diagnostics). A flag is "set" when its value is a
non-empty string that is not `0`, unless documented otherwise. See the index
for global notes.

## PE bridge / recorder

`DXMT9_OFFLOAD_COMMIT_REPLAY` and its inline rollback are stable producer-replay
providers. `DXMT9_CPU_READY_TAPE` is the migration alias for the stable
default-off streaming provider. Inline-constant delta remains an experimental
candidate; recorder stats, full snapshots, and queue-size overrides are
diagnostic or tuning surfaces rather than provider modes.

| Var | Purpose | Default |
|---|---|---|
| `DXMT9_PE_RECORDER_STATS` | Emit PE recorder aggregate stats. Current fields include chunk fill/first-record/active-fill/inter-append cadence, top `previous record -> next record` inter-append pairs, focused inter-append pair call-family attribution, selected post-Present PE call return HRESULT rows including failure returns, append CPU, VS/PS float constant setter CPU, const-flush CPU, `chunkBarrierFlush` const-drain CPU, APPLY_STATE packet-build CPU, and PE hot-state setter family call/dirty/CPU counters | `0` |
| `DXMT9_PE_RECORDER_CHUNK_LOG` | Emit PE recorder chunk boundary logs | `0` |
| `DXMT9_PE_INLINE_CONST_DELTA` | Experimental candidate that emits pending VS/PS constant dirty ranges inside canonical draw-record constant sections instead of standalone constant records. The mechanism is covered and removes records, but H214's FPS result stayed inside noise; the stable fallback preserves standalone record ordering, and non-draw consumers plus UP draws still drain standalone records. | `0` |
| `DXMT9_PE_STATS_DECIMATION` | Low-perturbation alternative to `DXMT9_PE_RECORDER_STATS` for sizing the PE recorder core: numeric `N` samples every Nth event of the four hot scopes (the record append, `touchConstShadow`, `flushConstShadow`, and the state build -- still keyed `draw_packet_*` in the log, now timing `buildSparseState`) and emits a cumulative `[dxmt9-pe-decimated]` line every 60 presents at Info level (run with `DXMT_LOG_LEVEL=info`). Estimate per scope as `sampled_ms * N / presents`, **then subtract the instrument's own cost**: the same log line carries `null_scope_sampled` / `null_scope_ms`, an empty region timed with the identical clock pair, and the scope's real per-call cost is `raw_mean - null_mean`. This is not optional. Measured on GT2 2026-07-29 the clock pair costs `186 ns` per sample, which is `6%` of `appendRecordDirect`'s reading and **`92%`** of `touchConstShadow`'s — an uncalibrated reading put PE recording at `30.5%` of the frame when it is `16.1%`. Low perturbation and low bias are different properties: decimation delivers the first and nothing about the second, and varying `N` cannot expose it because the extrapolation reduces to `events * (true + bias) / presents`, independent of `N`. The tool is unusable for absolute cost wherever per-call cost approaches clock cost. Since 2026-08-01 it also carries three **D3D9 entry-level** scopes (`entry_const`, `entry_draw`, `entry_state`) covering the whole call the app made across 14 hot entry points, so `entry - inner` sizes the PE layer the four recorder scopes never saw; on GT2 that residual is `~15.4 ms/present` and the entry total is `~41%` of the frame (`state-churn-encode-append-decomposition.08`; `12.0` of that `21.4 ms` — `56%` of the entry total, `22.6%` of the frame — was an SWVP probe removed in `83a0b085` for `+29%` GT2 scene fps, `.11`). New scopes must be armed with `dxmt9PeArmDecimatedScope`, which performs the null-scope calibration read — the instrument costs ~180ns/sample and an uncalibrated short scope is wrong by more than it measures. **A new scope must also pick a `phaseOffset` distinct from any scope it nests inside or contains on the same calls.** Sampling is deterministic (`events % N == phaseOffset % N`), so two scopes whose counters advance in lockstep fire on identical call ordinals at every `N`, and the outer span then swallows the inner scope's entire instrument — calibration pair, `t0`, and destructor read — while its own null subtraction removes one. That put `entry_const` at `756 ns/call` (`16.5 ms/present`) when the truth is `~79 ns`, measured directly after the fix (`.10`); `N`-variation cannot expose it because the coincidence is total at every `N`. `peConstSetterDecimatedStats()` is phase `1` and `peDrawPacketDecimatedStats_` phase `2` for exactly this reason, and `dxmt9-core-device-com-spec` pins both the fix and the old coinciding shape. Parent-gated sub-scopes (`DxmtPeDecimatedPhaseTimer`) are exempt — they cost their parent one clock pair each, a known subtractable constant. Separately, avoid an `N` that divides a periodic structure in the measured population: both `64` and `16` divide the 64-record chunk period, which aliases `append`'s once-per-64 flush tail and explains its `12.8%` cross-rate disagreement. `const_setter` samples are additionally split into per-call register-count buckets (`const_setter_n{1,2,3_4,5_8,9_16,gt16}_*`) so flat-versus-sloping cost distinguishes fixed entry overhead from per-element work. H213 verified `N=64`/`N=16` runs stay inside the healthy presents population (vs `-34%` throughput for full stats) and agree within `+/-12%` per site. Independent of `DXMT9_PE_RECORDER_STATS`; `0`/unset disables with near-zero cost | `0` |
| `DXMT9_PE_DRAW_FULL_SNAPSHOT` | Force every draw packet to ride a full PE state snapshot instead of the default delta. Applied in `src/d3d9/d3d9_pe_producer.cpp::buildSparseState` (the `snapshot` gate); the predicate itself is `dxmt9PeFullSnapshotEnabled()` in `src/d3d9/d3d9_pe_producer.hpp`. Trade-off: wire size grows ~10x (typical record ~100 B → ~1 KB), every draw carries a full state section set so none can be elided, but each record is replayable in isolation — debug / stress / out-of-order-replay only. Equivalence with the default delta path is regression-guarded by `tests/native/bridge/pe_full_snapshot_equivalence_spec.cpp`. | `0` |
| `DXMT9_PE_CHUNK_MAX_RECORDS` | Override max pending PE chunk records before commit | `64` |
| `DXMT9_PE_CHUNK_MAX_BYTES` | Override max pending PE chunk bytes before commit | `262144` |
| `DXMT9_RENDER_TAPE_CAPTURE` | Opt-in PE Render Tape v2 capture owner. `1` enables the device-owned value registry at device creation; the first successful Present builds a canonical `APPLY_STATE|FULL_SNAPSHOT` checkpoint from the PE shadow, closes exact descriptors, immutable payloads, and complete CPU-owned resource seeds, and arms the next Present interval when an artifact publisher is installed. An injected bootstrap producer is only an explicit test override. Publication is transactional as one value-owned events-plus-verified-blobs bundle; unset/`0` leaves callbacks, registry allocation, the recorder, and canonical chunk bytes untouched. | `0` |
| `DXMT9_RENDER_TAPE_OUTPUT_ROOT` | Explicit **PE-visible absolute directory** under which the internal PE publisher creates unique `frame-<monotonic>-<sequence>/` bundles. Under Wine this means a Windows drive-qualified path such as `Z:\\...`, not a host-only POSIX path. Relative roots, traversal components, NULs, symlink components, and existing-name collisions are rejected; staging is same-filesystem and renamed atomically only after `events.bin`, digest-named `blobs/`, and `manifest.json` are flushed. Unset means the production publisher is not installed and capture remains inert. | unset |
| `DXMT9_OFFLOAD_COMMIT_REPLAY` | Stable producer-replay provider selector: `0` keeps inline replay and `1` defers record replay to a device-owned FIFO worker after synchronous validation/import/retention. Both modes preserve direct-call drains and Present-boundary semantics under `R-BACK-2.51`; replay failures fail-stop the worker. Promotion proof passed in H195, and the engine default flipped to offloaded on 2026-07-10 (`d45af067`); explicit `0` remains the supported rollback. The experiment launcher pins the value only for recipe determinism and does not define the engine default. `DXMT9_OPTIMIZE_OPAQUE_DEPTH_INDEX_CACHE` unset follows the resolved offload state as an explicit coupled policy. | `1` (engine; explicit `0` opts out) |
| `DXMT9_CPU_READY_TAPE` | Migration alias for the stable `streaming` source-delivery provider in `R-BACK-2.66`. With commit-replay offload active, eligible canonical chunks reserve bounded `CpuReadyTape` storage and publish typed source payloads; ordered Legacy/Inline/control fallbacks remain valid. Streaming remains default off pending `R-BACK-2.50` visual, locality, no-gputrace, and performance gates, but the mode is a preserved renderer-provider path rather than a disposable experiment. A future canonical source selector will take precedence after it is implemented and added to these descriptive rules. | `0` |
| `DXMT9_OFFLOAD_QUEUE_CHUNKS` / `DXMT9_OFFLOAD_QUEUE_BYTES` | Raw-chunk queue bounds for the commit-replay offload worker (count / bytes). H191 attribution showed the defaults never block a push in GT1 (`offload_push_backpressure_waits=0`), so these are dormant tuning knobs, not active levers | `64` / `8388608` |
