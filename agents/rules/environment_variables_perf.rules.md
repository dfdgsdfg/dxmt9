# dxmt9 Environment Variables — Perf counters

Part of the [`environment_variables.rules.md`](environment_variables.rules.md)
index (counter system, per-frame snapshot, and 3DMark05 GT1 perf-probe knobs).
A flag is "set" when its value is a non-empty string that is not `0`, unless
documented otherwise. See the index for global notes, and
[`metal_debugging.rules.md`](metal_debugging.rules.md) §9 for the 3DMark05 GT1
perf-probe toolkit.

## Perf counters

| Var | Purpose | Default |
|---|---|---|
| `DXMT_PERF_COUNTERS` | Enable `[dxmt9-perf]` counter line at exit | `0` |
| `DXMT_PERF_COUNTERS_PERIODIC_PRESENTS` | Emit counters every N presents (numeric) | `0` |
| `DXMT9_PERF_FRAME_SAMPLING` | Per-frame counter delta snapshots | `0` |
| `DXMT9_PERF_ENCODER_GPU_TIME` | Opt-in per-encoder GPU-time via counter sample buffers at render-encoder boundaries; pairs with `DXMT_PERF_COUNTERS`. See `metal_debugging.rules.md` §5 path B | `0` |
| `DXMT9_PERF_ENCODER_BREAKDOWN` | Emit per-render-encoder `[dxmt9-perf-encoder]` summary and `[dxmt9-perf-encoder-stream]` stream breakdown lines for stream handle/offset/stride churn, stream Metal-bind first/handle/offset reasons, stream/IB unique handle bytes/usage/pool buckets, IB handle churn, primitive/vertex/FFP/pre-transformed geometry shape, PSO/shader-variant/VSOut-layout attribution including layout-cache hit/miss counts, VS/PS shader hash and, when `DXMT_DUMP_SHADER_DIR` is set, exact VS/PS source hash attribution, argbuf table/cbuf byte totals, setVertexBytes slot-5/other bytes, transient vertex/index bytes split by UP preupload, decl/shadow fallback, and indexed expansion, VS float upload-plan ranges, and write attribution | `0` |
| `DXMT9_PERF_ENCODER_BREAKDOWN_CBUF_CONTENT` | Heavy opt-in extension for `DXMT9_PERF_ENCODER_BREAKDOWN=1`. Enables byte-by-byte VS/FFPVS cbuf content-history scans and first/rewrite/field-split columns. Keep off for normal CPU baselines because it runs on cbuf upload hot paths and is visible as `encode_draw_argbuf_cbuf_observer_cpu_ms` | `0` |
| `DXMT9_PERF_ENCODER_BREAKDOWN_SEQ` | Optional numeric filter for `DXMT9_PERF_ENCODER_BREAKDOWN=1`; when set, emit encoder breakdown rows only for one render-pass sequence id such as frame-capture `seq=60`, keeping 3DMark05 no-gputrace logs bounded during per-frame attribution probes | unset |
| `DXMT9_PERF_ENCODER_BREAKDOWN_SEQ_MIN` / `DXMT9_PERF_ENCODER_BREAKDOWN_SEQ_MAX` | Optional inclusive numeric range filter for `DXMT9_PERF_ENCODER_BREAKDOWN=1`; used by Metal System Trace sidecars to log only the xctrace wall-clock seq window instead of all frames. Ignored when `DXMT9_PERF_ENCODER_BREAKDOWN_SEQ` is set | unset |
| `DXMT9_PERF_RENDER_PASS_REENTRY_TOP` | Optional top-N per-frame same-key render-pass re-entry diagnostic. Emits `[dxmt9-perf-render-pass-reentry]` rows with A/B attachment handles, true B->A encoder path, read-relation bits, store-proof owners, touch distances, and preservation bytes. Use with `DXMT9_PERF_ENCODER_BREAKDOWN=1` or wrapper `--render-pass-reentry-top N` when joining re-entry role pairs to encoder load/store/clear action shape | unset |
| `DXMT9_PERF_DRAW_PACKET_ACTUAL_CHANGE` | Opt-in commit_chunk draw-packet diagnostic. Before applying a packet delta, compare the declared state bits to the current unix-side `DeviceState` and count actual-changing vs redundant non-binding/uniform buckets. Wrapper flag: `run_3dmark05_perf_probe.sh --probe-draw-packet-actual-change` | `0` |
| `DXMT_3DMARK05_DUMP_FRAMEGRAPH_DAG` | 3DMark05 perf wrapper default for `--dump-framegraph-dag`; writes renderer DAG dumps under `traces/<run-id>/analysis/dag` and runs `summarize_framegraph_dag.py` after the run when JSON files exist | `0` |
| `DXMT_3DMARK05_DUMP_FRAMEGRAPH_DAG_FRAME` | Wrapper default for `--framegraph-dag-frame`; forwarded as `DXMT9_RENDERER_DUMP_DAG_FRAME`. If unset and DAG dumping is enabled, the wrapper scopes it to `--frame` to avoid unbounded 3DMark05 dumps | derived |
| `DXMT_3DMARK05_DUMP_FRAMEGRAPH_DAG_FRAME_RADIUS` | Wrapper default for `--framegraph-dag-frame-radius`; forwarded as `DXMT9_RENDERER_DUMP_DAG_FRAME_RADIUS` | `0` |
| `DXMT_3DMARK05_DUMP_FRAMEGRAPH_DAG_FORMATS` | Wrapper default for `--framegraph-dag-formats`; forwarded as `DXMT9_RENDERER_DUMP_DAG_FORMATS`. Keep `json` in the list if the wrapper post-run summary is desired | `json,mermaid` |
| `DXMT_3DMARK05_DUMP_FRAMEGRAPH_DAG_OPTIMIZE` | Wrapper default for `--framegraph-dag-optimize`; forwarded as analysis-only `DXMT9_RENDERER_DUMP_DAG_OPTIMIZE` such as `passcoalesce` | unset |
| `DXMT_3DMARK05_DUMP_FRAMEGRAPH_DAG_DRAWS` | Wrapper default for `--framegraph-dag-draws`; forwarded as `DXMT9_RENDERER_DUMP_DAG_DRAWS=1` when nonzero | `0` |
| `DXMT9_PERF_STREAM_BIND_PHASE_SPLIT` | Heavy opt-in stream-bind phase attribution. Enables the raster, FFP-stream, shader-stream, texture/sampler, and index-phase CPU child timers under the aggregate `encode_draw_stream_bind_cpu_ms`; the phase call counters and parent stream-bind timer remain live by default. Use only for no-gputrace CPU attribution probes because it adds clock calls around every draw's bind phases | `0` |
| `DXMT9_PERF_TEXTURE_SAMPLER_DIRECT_SPLIT` | Heavy opt-in per-entry attribution for the fragment texture/sampler direct lane: texture resolve, direct texture branch/set, direct sampler branch/set. Use only for short no-gputrace CPU attribution probes because the nested scopes perturb the default perf profile | `0` |
| `DXMT9_PERF_BINDING_PACKET_PLAN_SPLIT` | Heavy opt-in binding-packet plan attribution. Splits `encode_draw_binding_packet_plan_cpu_ms` into fragment texture/sampler, vertex texture/sampler, programmable VS extra-stream, and raster-plan children. Use only for short no-gputrace CPU attribution probes because the nested scopes perturb the default perf profile | `0` |
| `DXMT9_PERF_DRAW_ISSUE_SPLIT` | Heavy opt-in draw-issue attribution. Splits `encode_draw_issue_cpu_ms` into indexed, non-indexed, expanded-indexed, split-indexed, Metal draw-call, and visibility-scout children. Use only for no-gputrace CPU attribution probes because it adds nested timers around every draw issue | `0` |
| `DXMT9_PERF_ARGBUF_REOPEN_SPLIT` | Heavy opt-in Stage 2 argbuf reopen attribution. Splits the post-open reopen path into table probe, table shadow store, byte accounting, cbuf cache probe, dirty scans, and dirty-mask force timers. Use only for no-gputrace CPU attribution probes because the nested timers perturb the default per-draw argbuf path | `0` |
| `DXMT9_PERF_ARGBUF_CBUF_PROBE_SPLIT` | Heavy opt-in argbuf cbuf probe/repoint attribution. Enables cached-repoint and content-probe CPU timers, including VS/PS/FFPVS/FFPPS stage splits. Default profile keeps the non-timed calls/bytes/hit counters only. Use this only for no-gputrace CPU attribution probes because it adds timer scopes on the per-draw argbuf reopen path | `0` |
| `DXMT9_PERF_ARGBUF_CBUF_DIRTY_IDENTITY` | Heavy opt-in argbuf cbuf dirty-update attribution. For dirty VS cbuf uploads, compares the current VS cbuf identity against the encoder-local cached binding and counts hit/miss/no-cache plus bytes. Use only for no-gputrace CPU attribution probes; it does not change rendering behavior | `0` |
| `DXMT9_PERF_ARGBUF_PAYLOAD_DELTA` | Heavy opt-in argbuf reopen attribution. Compares each Stage 2 draw's payload hash and VS/PS constant component hashes against the previous successfully encoded draw in the same render encoder, splitting first draw, same payload, changed payload, VS/PS changed, float/int/bool changed within each shader stage, VS/PS float-register delta width, `<=1`/`<=4`/`<=16`/`<=64`/`>64` bucket row counts and register sums, VS float prefix/span/full-prefix shape, non-constant-only changed, resource-array forced reopen counts, and constants-only cbuf-table reopen counts that bound the Stage 2b/direct-cbuf table-churn opportunity. Use only for no-gputrace CPU attribution probes; it does not change rendering behavior | `0` |
| `DXMT9_PERF_ARGBUF_PAYLOAD_DELTA_SOURCE` | Heavy opt-in companion to `DXMT9_PERF_ARGBUF_PAYLOAD_DELTA`. Aggregates VS float payload-delta rows by VS/PS shader hash and active prefix width, emitting bounded `[dxmt9-perf-argbuf-payload-delta-source]` lines for source attribution. Use only for no-gputrace attribution probes; it does not change rendering behavior | `0` |
| `DXMT9_PERF_VS_CONST_SETTER_RANGE` | Heavy opt-in PE-side companion to argbuf cbuf attribution. Aggregates `SetVertexShaderConstantF` app-call ranges and the flushed VS float constant records by current VS/PS shader hash, start, and count, emitting bounded `[dxmt9-perf-vs-const-setter-range]` lines at present/destructor. Use wrapper flag `run_3dmark05_perf_probe.sh --probe-vs-const-setter-range` to decide whether full-prefix VS argbuf churn comes from real app setter ranges, PE dirty-range merging, or later backend upload/table policy; it does not change rendering behavior | `0` |
| `DXMT9_PERF_COMPLETION_SIGNAL_DELAY_MS` | Heavy opt-in present-pacing perturbation. After `waitUntilCompleted()` returns, sleep this many milliseconds before publishing the completed seq/waterline (clamped to 250ms). Use for A/B tests that distinguish app-side fixed cadence from a true dependency on dxmt9 completion publication; never use in normal perf baselines | `0` |
| `DXMT9_PERF_ENCODE_SLOT_PSO_SEMANTIC_SPLIT` | Heavy opt-in encode-slot PSO semantic-memo attribution. Enables the semantic key/probe/store CPU timers around the default semantic memo. The memo hit/miss/overflow counters remain live by default; this flag is only for short no-gputrace CPU attribution probes because it adds clock calls on the per-draw prefetch path | `0` |
| `DXMT9_PERF_ENCODE_SLOT_PSO_SEMANTIC_MISS_SPLIT` | Heavy opt-in encode-slot PSO attribution. For semantic-memo misses that later hit the slot-local probe-key memo, compares the current semantic source against the first probe-key memo entry and classifies which conservative semantic fields changed: argbuf selector, vertex declaration, shader, render state, texture handles, texture LOD, TSS, sampler, attachment, clip plane, constant usage, hash-only, or unknown. It also emits single-field/multi-field and texture-handle-only counters to size a future resource-shape PSO memo. Use only for no-gputrace CPU attribution probes because it adds comparisons and counter writes on the per-draw prefetch path | `0` |
| `DXMT9_PERF_ENCODE_SLOT_PSO_RESOURCE_SHAPE_OPPORTUNITY` | Heavy opt-in encode-slot PSO attribution. Builds a slot-local pre-resolve memo key that intentionally ignores exact texture handles while keeping the rest of the conservative semantic shape, then validates each hit after `resolveDrawPipelineState()` by comparing the final canonical probe key including active texture mask/type, X8 alpha-fill mask, attachment formats/blend/sample count, sampler LOD-bias, and VSOut layout. It does not change rendering behavior and should be used only for short no-gputrace CPU opportunity probes | `0` |
| `DXMT9_DISABLE_DRAW_UNIFORM_PAYLOAD_DEDUP` | CPU attribution probe for draw-run append uniform payload storage. When set, append every materialized `DrawUniformPayload` and skip the slot-local payload lookup/dedup table. Use only for no-gputrace A/B runs that compare lookup CPU removed against extra payload records/bytes | `0` |
| `DXMT9_DISABLE_ENCODE_SLOT_PSO_RESOURCE_SHAPE_MEMO` | Opt out of encode-worker texture-handle-blind resource-shape draw-PSO memoization. The default memo handles semantic-memo misses by probing a slot-local resource-shape key and reusing the memoized `PsoHandle` on a hit, bypassing repeated `resolveDrawPipelineState()` / canonical probe-key construction. If `DXMT9_PERF_ENCODE_SLOT_PSO_RESOURCE_SHAPE_OPPORTUNITY=1` is also set, the non-mutating validation path wins and this default behavior does not shortcut hits | `0` |
| `DXMT9_DISABLE_ENCODE_SLOT_PSO_SEMANTIC_MEMO` | Opt out of encode-worker slot-local draw-PSO semantic memoization. The default memo reuses a final `PsoHandle` within one chunk slot when cheap snapshot hashes, attachment/texture handles, shader layout shape, and argbuf selector bits match a previously resolved state, bypassing repeated key/source-context resolution after the first authoritative lookup | `0` |
| `DXMT9_DISABLE_ENCODE_SLOT_PSO_PROBE_KEY_MEMO` | Opt out of encode-worker slot-local draw-PSO probe-key memoization. The default memo reuses a final `PsoHandle` within one chunk slot after the first authoritative cache lookup for the same canonical probe key, reducing repeated `getOrBuildDrawPipelineHandle` cache calls while preserving miss/overflow fallback | `0` |
| `DXMT_3DMARK05_REQUIRE_UNLOCKED` | 3DMark05 launcher guard: fail early when macOS reports `CGSSessionScreenIsLocked=Yes`, avoiding false black/factory-only perf captures. Set to `0` only for deliberate locked-session experiments | `1` |
| `DXMT_3DMARK05_PREFIX` | Direct 3DMark05 launcher prefix override. `run_3dmark05_perf_probe.sh` sets this to `experiments/prefixs/app-d3d9-3dmark05` so standard probes use the catalogue app prefix even if the optional `app-d3d9-3dmark05-verify` prefix was cleaned up | launcher default: verify prefix |
| `DXMT_3DMARK05_RESULT_FILE` | Append a 3DMark05 result-file argument such as `dxmt9_gt1.3dr` after the selected command-line tests, enabling documented unattended result runs when the desktop is unlocked | unset |
| `DXMT_3DMARK05_PROBE_TIMEOUT` | Default runner timeout for `run_3dmark05_perf_probe.sh`; when unset the wrapper uses `420s` with gputrace and `120s` with `--no-gputrace`, passes that value to `run_experiment.py --timeout`, and rejects disabled/zero timeouts because 3DMark05 may hang on the final frame | derived |
| `DXMT_3DMARK05_PROBE_TIMEOUT_SLACK` | Extra seconds added to the perf wrapper's top-level watchdog beyond `DXMT_3DMARK05_PROBE_TIMEOUT` / `--timeout` plus the effective capture delay. The watchdog runs the whole `caffeinate run_experiment.py ...` command in a fresh process group and terminates it if the catalogue runner does not return after its own timeout/finalization window | `45` |
| `DXMT_3DMARK05_SET_MTL_CAPTURE_ENABLED` | Opt back into adding `MTL_CAPTURE_ENABLED=1` for 3DMark05 perf-probe gputrace runs. Keep unset for normal probes because `MTL_CAPTURE_ENABLED=1` alone has reproduced black-screen startup with draw/present counters at zero | `0` |
| `DXMT_3DMARK05_METAL_CAPTURE_DESTINATION` | Forwarded to `DXMT_METAL_CAPTURE_DESTINATION` by the 3DMark05 perf wrapper; wrapper flag `--metal-capture-destination` / `--xcode-developer-tools-capture` can set it per run. Use `developerTools` only for an attached-Xcode, normal-start diagnostic after preflighting that Xcode can attach to the real Wine child and choosing a target frame the run will reach. It does not write `frame<N>.gputrace` directly, so the wrapper proves `destination=1` start/stop log lines instead of requiring a file. Otherwise default file `.gputrace` capture remains `gpuTraceDocument` | unset |
| `DXMT_3DMARK05_ALLOW_NO_FILE_CAPTURE_LAYER` | Disable the wrapper's file `.gputrace` capture-layer preflight. Use only when intentionally collecting a late `Capture layer is not inserted` failure; normal file capture runs should fail before launch if the Wine child lacks `MetalCaptureEnabled` and neither `DXMT_3DMARK05_SET_MTL_CAPTURE_ENABLED` nor an explicit `MTL_CAPTURE_ENABLED` / `METAL_CAPTURE_ENABLED` env is set | `0` |
| `DXMT_3DMARK05_REQUIRE_XCODE_ATTACH_PREFLIGHT` | Require `run_3dmark05_perf_probe.sh` to query Xcode's Debug attach menu before launching a `developerTools` capture run. Equivalent to wrapper `--require-xcode-attach-preflight`; fails before launch when attach-by-PID is disabled and the process list is stuck at `Getting Process List...` | `0` |
| `DXMT_3DMARK05_OSASCRIPT_BIN` | Override the `osascript` binary used by the wrapper's Xcode attach preflight. Intended for tests or explicit local diagnostics; normal runs use `/usr/bin/osascript` via PATH | `osascript` |
| `DXMT_3DMARK05_DEVTOOLS_SECURITY_BIN` | Override the `DevToolsSecurity` binary used by the wrapper's Xcode attach preflight. Intended for tests or explicit local diagnostics; normal runs use `/usr/sbin/DevToolsSecurity` and fail early when Developer Mode is disabled | `/usr/sbin/DevToolsSecurity` |
| `DXMT_3DMARK05_DIRECT_TIMEOUT` | Timeout used by `scripts/run_apps/run_app-d3d9-3dmark05-verify_direct.sh` for manual direct-prefix runs. The wrapper kills the process group on timeout so a final-frame hang does not require manual cleanup | `120` |
| `DXMT_3DMARK05_DIRECT_DRY_RUN` | Print the direct 3DMark05 wrapper timeout and launcher command without starting Wine | `0` |
| `DXMT_3DMARK05_LAUNCHER_TIMEOUT` | Direct-shell fallback timeout used by `experiments/launchers/app-d3d9-3dmark05.sh` only when it is not already supervised by `run_experiment.py` or the direct wrapper. Set a positive value for longer manual suites; disabled/zero values are rejected | `120` |
| `DXMT_3DMARK05_ALLOW_UNSUPERVISED` | Bypass the 3DMark05 launcher's direct-shell fallback timeout. Use only when another documented supervisor owns process lifetime | `0` |
| `DXMT_3DMARK05_KILL_SERVER_ON_EXIT` | Direct 3DMark05 launcher cleanup: kill the app prefix wineserver on normal exit or TERM/INT so timeout-finalized runs do not leave a detached 3DMark05 process alive | `1` |
| `DXMT_3DMARK05_MIN_TRACE_FREE_MB` | `run_3dmark05_perf_probe.sh` free-space guard before launching Wine/gputrace; defaults to `2048` with gputrace and `256` with `--no-gputrace` | derived |
| `DXMT_3DMARK05_CLASS_PROXY_TOP` | Default top-N indexed state/class proxy rows emitted by `finalize_3dmark05_perf_probe.sh` after Xcode/dxmt joining; use it to bound `frame<N>-indexed-state-class-xcode-proxy.{md,csv}` | `12` |
| `DXMT_3DMARK05_MAX_TOP_UNEXPLAINED_BUFFER_WRITE_RATIO` | Default for the Xcode comparison gate `--max-top-unexplained-buffer-write-ratio`, failing candidates whose top encoder buffer-write traffic remains mostly unexplained by dxmt CPU-side writers | unset |
| `DXMT_3DMARK05_MAX_CONST_UPLOAD_BREAK_COUNT_RATIO` | Default for the run-level comparison gate `--max-const-upload-break-count-ratio`, failing sparse/coalesced constant-upload candidates that reduce bytes by creating too many const-upload draw-run breaks | unset |
| `DXMT_3DMARK05_SYSTEM_TRACE_CPU_PRODUCER_THREAD_REGEX` | Default for `run_3dmark05_system_trace_sidecar.sh --cpu-producer-thread-regex`; when set, the xctrace CPU summary verdict treats the matching thread as the P4 producer instead of auto-selecting the highest-weight target-process thread | unset |
| `DXMT_3DMARK05_SYSTEM_TRACE_CPU_PRODUCER_FROM_PE_LOG` | Default for `run_3dmark05_system_trace_sidecar.sh --cpu-producer-from-pe-log`; forces PE recorder stats/log info when no explicit regex is set, passes the wrapped probe's `3dmark05-direct.log` to the CPU summarizer, and lets it prefer unix-side `unix_commit_chunk_entry native_tid=0x...` selectors before falling back to PE `pe_present_* thread_id=0x...` selectors. PE ids are Win32 thread ids, so a PE-source `producer-thread-not-found` verdict means native Mach/pthread mapping is still needed | `0` |
| `DXMT_3DMARK05_SYSTEM_TRACE_MIN_FREE_MB` | Free-space guard for `run_3dmark05_system_trace_sidecar.sh` before launching xctrace. Set `0` only for deliberate partial-run risk; dry-runs print a warning instead of failing | `2048` |
